A good plan is a bet about the world. It says: given what I know now, these are the steps that seem worth taking. The trouble begins when an agent treats that bet as a promise.

Imagine a research assistant searching for the source of a result. It finds a plausible paper, builds a summary around it, and then discovers that the experiment used a different model. The new information is small. Its consequences are not. Some earlier reasoning now needs to be discarded.

## A task with a turning point

An environment could make this moment explicit. The agent begins with a reasonable set of assumptions. Halfway through, an observation contradicts one of them. Solving the task requires recognizing which part of the plan depended on that assumption.

This is different from putting an obstacle in the way. A locked door might require a key; a changed destination might require abandoning the door altogether.

> The interesting question is not whether the agent can make a plan. It is whether the plan remains answerable to evidence.

A useful task would leave a trace we can inspect: the original assumption, the contradictory observation, the revised action, and the final result. The final answer alone may hide the difference between principled revision and a lucky detour.

## Three things to measure

The evaluation could distinguish between noticing, revising, and recovering. Each answers a different question.

| Stage | Question | Observable behavior |
| --- | --- | --- |
| Notice | Did the new evidence register? | The agent identifies a conflict. |
| Revise | Did it update the relevant belief? | The next action changes for a reason. |
| Recover | Did the revision help? | The task is completed under the new conditions. |

An agent could pass the first stage in words and still fail the second in action. It might write that the situation has changed, then execute the same steps it already intended to take. This is one reason to inspect a trajectory, not just a summary of it.

## Rewarding the result without rewarding theatre

A verifier should reward behavior that actually depends on the changed state. Merely asking the agent to say “I changed my mind” creates an easy substitute for doing so.

```python title="a small evaluation sketch"
def evaluate(before, after, trajectory):
    result = check_final_state(after, trajectory)
    observed = saw_relevant_evidence(trajectory)
    return {
        "task_solved": result,
        "evidence_observed": observed,
    }
```

This sketch deliberately keeps the outcome and the observation separate. The two checks would need task-specific implementations. Combining them into one reward is another design decision, not an automatic next step.

There is a further complication: revision has a cost. An agent that restarts every time it encounters a surprise may waste just as much effort as one that never revisits anything. The target is selective reconsideration.

## The next experiment

Start with a pair of tasks that share an opening. In one version, the original assumption remains true. In the other, it becomes false. Compare the actions after the point where evidence diverges.

The interesting result would be an agent that keeps going when the plan is still sound, and turns back when it is not. That is a more demanding behavior than either persistence or doubt alone.
