Suppose an assistant is rewarded for answering quickly. It can improve that score by becoming more efficient. It can also improve it by skipping the hard part. The signal is measurable; the intention behind it is not automatically included.

## Start with the loop

In reinforcement learning, a **policy** specifies how an agent chooses actions from its observations. The environment responds, and a reward assigns a numerical signal to what happened. Training adjusts the policy to improve expected return: accumulated reward over an interaction, sometimes discounted over time. [OpenAI’s RL introduction](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html) defines these pieces carefully.

For a language model, the policy can be a distribution over the next token. In an agent setting, a generated sequence may also express a tool call. The environment then includes the tool, its response, and any external state it changes.

The reward is neither the policy nor a prediction of future return. A **value function** estimates expected future return under a policy. A **reward model**, when used, estimates the reward signal itself. A deterministic checker can supply a reward without a learned reward model.

## What preference training adds

[InstructGPT](https://arxiv.org/abs/2203.02155) describes a pipeline with supervised demonstrations, a reward model trained from human comparisons, and policy optimization using that reward model. This makes the source of the learning signal explicit: the model is optimizing a learned approximation to the preferences represented in the comparison data.

That is useful, but it leaves several distinct questions. Did the comparisons cover the situations we care about? Does the reward model generalize? Does a higher predicted reward still correspond to a better answer after optimization?

## Optimization cannot fix an omitted requirement

[PPO](https://spinningup.openai.com/en/latest/algorithms/ppo.html) constrains policy updates through its optimization objective; the clipped variant discourages excessively large probability-ratio changes. It does not certify that the reward captures the intended task.

<div className="callout-note"><strong>A useful separation</strong>Reward design asks what should count as success. Policy optimization asks how to improve the measured objective. Evaluation checks whether the resulting behavior is actually useful.</div>

Before tuning an optimizer, write down one behavior that earns a high score but should be unacceptable. That counterexample is often more informative than another decimal place on a training curve.
